# Invoice auditing

This solution identifies billing errors by comparing hospital invoices with their contracts. First, Python extracts the contract rules, while Claude matches invoice descriptions to contracted services. Python then checks prices, quantities, dates, discounts, duplicate billing and invoice calculations to flag errors and calculate the expected totals.

The submission covers **Hospitals 4 and 5: 1,885 invoice IDs, 139 flagged**. Hospital 1 is used for development. I focused on Hospitals 4 and 5 because their contracts were clearer and more structured. Hospitals 2 and 3 had longer and more complex documents that would have required more time than the budget allowed. No accuracy is claimed for Hospitals 4 and 5 because their labels are unavailable.

## Reproduce the submission

Use **Python 3.11** (tested with 3.11.2). Clone this repository and open a terminal in its root directory. Runtime dependencies, including pandas dependencies, are pinned in `requirements.txt`.

In PowerShell:

```powershell
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt
.venv/Scripts/python -B src/extract_rules.py --hospital 4
.venv/Scripts/python -B src/extract_rules.py --hospital 5
.venv/Scripts/python -B src/audit_invoices.py --submission
```

Installation needs access to a Python package index. After installation, the pipeline runs locally: **no API key, model download or Claude account is needed**. It uses the saved service matches in the [claude matching service](claude%20matching%20service/) folder. The default run builds Hospitals 4 and 5 and the final submission.

These commands rebuild contract JSON and predictions, validate the submission, and write **[`outputs/submission.csv`](outputs/submission.csv)**. Generated files are overwritten. Rows contain Hospital 4 followed by Hospital 5, in original header order, with one row per distinct invoice ID.

## How it works

1. **Extract rules.** `src/extract_rules.py` reads the supported Markdown contracts into service tables: rates, caps, premiums, bundles, discounts and exclusions. Hospital 5 also has facility and plan multipliers. The parser checks table structure and rule references.
2. **Identify services.** Claude matches each invoice description to a service listed in the contract, including descriptions with abbreviations or different wording. If several services could match, it also checks the billed unit and price. `UNKNOWN` means the described service is not in the contract. `UNSURE` means there is not enough information to choose a service confidently.
3. **Audit invoices.** `src/audit_invoices.py` checks contract numbers, dates, prices, billing units, quantity limits, duplicate charges and invoice totals. It also checks discounts, extra charges, special prices for services provided together. It flags errors and calculates what each invoice should total when enough information is available.
4. **Assemble results.** Running `src/audit_invoices.py --submission` audits Hospitals 4 and 5 and combines their predictions into `outputs/submission.csv`. It checks that the file follows the template, includes each invoice ID once, uses whole cents, preserves billed totals and has confidence values between 0 and 1.
